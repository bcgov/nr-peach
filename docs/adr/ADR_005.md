- **Status:** Accepted
- **Decision Date:** 2026-09-17
- **Deciders:** PEACH Design Team
- **Category:** Database, Operations, Compliance
- **Supersedes:** ADR-002 (Chisel-based database access)

## Context

To maintain compliance with secure database access requirements and perform operational maintenance and support for
Azure hosted databases, we need a clean and documented way to establish a direct JDBC connection with the remote
database. In addition, we must ensure that the way we connect to the database is secure, follows best practices for
authentication, authorization, and encryption, and aligns with organizational security policies.

A previous decision adopted Chisel as the tunneling mechanism. However, security and compliance requirements now mandate
a migration to Azure Bastion as the approved solution for database access. This solution must be toggleable, cost
effective (not to exceed $100/month additional), allow seamless local DBeaver connections via tunneling, and maintain
air gaps between operational tools and development, test, and production environments.

## Decision

PEACH operations will migrate to [Azure Bastion](https://learn.microsoft.com/en-us/azure/bastion/bastion-overview) for
all secure connections to remote Azure PostgreSQL databases. The Bastion host will be deployed within the PEACH
infrastructure using Terraform, modelled after proven Azure Landing Zone implementations. The solution will be
toggleable and support direct local DBeaver connections via tunneling to eliminate the need for Chisel-based tunnels.

## Rationale

Azure Bastion provides a managed, hardened access solution for connecting to Azure resources without exposing them to
the public internet. The migration addresses compliance requirements while offering several advantages over the previous
Chisel-based approach:

- **Compliance:** Azure Bastion aligns with organizational security policies and regulatory requirements for database
  access.
- **Native Integration:** Bastion is a first-class Azure service designed specifically for secure resource access,
  reducing operational complexity compared to third-party tunneling solutions.
- **Air Gap Assurance:** A dedicated tools subscription can isolate Bastion infrastructure from development, test, and
  production environments, strengthening security boundaries.
- **Cost Efficiency:** Within identified budget constraints ($100/month additional), Bastion remains cost-effective when
  properly sized and toggled off when not in use.
- **Proven Templates:** BC Government reference implementations provide validated Terraform modules and deployment
  patterns for rapid integration into existing infrastructure.

### Assumptions

- Azure Bastion will be deployed to a dedicated tools subscription to maintain air gap isolation from development, test,
  and production environments.
- The Bastion solution will be toggleable to control costs and operational exposure.
- DBeaver and other local database tools will connect through Bastion via secure tunneling without requiring Chisel.
- The Bastion deployment will be defined as infrastructure-as-code using Terraform and version-controlled within the
  PEACH project.
- A dedicated vnet or peering configuration will enable connectivity from Bastion to Azure PostgreSQL without exposing
  the database to the public internet.
- Existing Chisel documentation and tooling will be deprecated in favor of Bastion-based workflows.

## Options Considered

- **Do nothing:** Continue using Chisel for database access. Rejected because it does not satisfy compliance
  requirements and does not align with organizational security policies.
- **Use Chisel (previous decision):** Maintain the existing Chisel-based tunnel infrastructure. Rejected due to
  mandatory compliance requirements that necessitate adoption of Azure Bastion.
- **Use Azure Bastion (chosen):** Migrate to Azure Bastion for all database access. Accepted because it provides a
  compliant, native Azure solution within budget constraints, enables seamless local tooling, and leverages proven BC
  Government reference implementations.

## Consequences

### Positive

- Compliance with organizational security policies and regulatory requirements is achieved through a managed, auditable
  Azure service.
- Operational overhead is reduced by leveraging Azure-managed infrastructure rather than maintaining a custom Chisel
  deployment.
- Air gap isolation between tools and production environments strengthens the security posture.
- Local development tools (eg. DBeaver) can connect directly to remote databases via Bastion tunneling without additional
  client configuration complexity.
- Terraform-based infrastructure-as-code enables repeatable, version-controlled, and auditable Bastion deployments.
- Leveraging proven BC Government templates accelerates implementation and reduces integration risk.

### Negative

- Initial investment required to design, implement, and validate Bastion integration into existing PEACH infrastructure.
- Operational team must be trained on new Bastion-based access workflows and retire Chisel procedures.
- Additional Azure subscription (tools subscription) may incur modest costs, though constrained within the $100/month
  budget.
- Legacy Chisel documentation and configurations must be deprecated and removed to avoid confusion during the transition.
- Bastion connectivity depends on vnet configuration and peering, requiring careful network design to maintain air gaps
  and security boundaries.
