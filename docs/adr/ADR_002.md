- **Deciders:** PEACH Design Team
- **Category:** Database, Operations

## Context

To perform operational maintenance and support for Azure hosted databases, we need a clean and documented way to
establish a direct JDBC connection with the remote database. In addition, we must ensure that the way we connect to the
database is also secure and follows best practices for authentication, authorization, and encryption.

## Decision

PEACH operations will use [Chisel](https://github.com/jpillora/chisel) (a fast TCP tunnel over HTTP) for connecting
local database tools (eg. DBeaver) to our remote Azure PostgreSQL database. The tunnel server runs on Azure App Service
and is password protected. Additionally, when not in use it is to be disabled/stopped as to not leave the connection
open.

## Rationale

Chisel offers a way for localhost clients to establish native JDBC socket connections via HTTPS proxy tunnel. This is
necessary because we cannot permit the database to be reachable to the public internet. By using Chisel, we can
securely tunnel connections from local clients to the remote database without exposing it directly.

### Assumptions

- Chisel will be used for all manual human database access and operations to Azure hosted databases.
- The Chisel tunnel server will be hosted on Azure App Service and will be password protected.
- The tunnel server must be disabled or stopped when not in use to prevent unauthorized access.
- The Chisel client configuration must be securely stored and managed to prevent unauthorized access to the tunnel.

## Options Considered

- **Do nothing:** Permit direct JDBC connections to Azure database without a secure tunnel. Rejected because it exposes
  the database to the public internet, increasing the risk of unauthorized access and potential security breaches.
- **Use Bastion:** Utilize Azure Bastion to securely connect to the database. Rejected because it introduces additional
  cost and complexity and may not provide the same level of seamless integration for local development as Chisel.
- **Use Chisel for secure tunneling (chosen):** Establish a Chisel tunnel for all remote database connections. Accepted
  because it provides a reasonably secure, manageable, and auditable way to connect to Azure hosted databases without
  exposing them to the public internet.

## Consequences

### Positive

- All database connections are routed through a secure tunnel, reducing the risk of unauthorized access.
- The use of Chisel provides a manageable and auditable way to control and monitor database access.
- Local development and operations can proceed without exposing the database to the public internet.

### Negative

- Additional operational overhead to start and stop the Chisel tunnel as needed.
- Users must securely manage Chisel client configurations to prevent unauthorized access.
- Potential latency introduced by tunneling database connections through Chisel.
- Detailed operational manual required to guide developers and operators in correctly using and managing the Chisel
  tunnel.
