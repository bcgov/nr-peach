- **Status:** Accepted

- **Deciders:** PEACH Design Team
- **Category:** Integrity, Validation

## Context

NR-PEACH requires robust validation of PIES JSON data across incoming API requests, outgoing responses, and internal
data transformations. As the system handles Protected B classified data with complex integrity requirements, it is
essential to enforce strict schema validation to prevent malformed or unauthorized data structures from entering the
system. The validation layer must be performant enough to handle high-throughput scenarios without becoming a
bottleneck, while maintaining compatibility with industry standard JSON Schema specifications.

## Decision

We will use AJV (Another JSON Schema Validator) as the primary JSON Schema validation library for NR-PEACH. AJV will be
used to validate all inbound and outbound data against defined JSON Schema specifications. The library will be
configured to support JSON Schema Draft 7 standard for all schema definitions within the system.

## Rationale

AJV is a high-performance, widely adopted JSON Schema validator that meets NR-PEACH's validation requirements across
multiple critical dimensions. The library delivers exceptional validation throughput, enabling the system to handle
high-volume data processing without introducing performance degradation. AJV's full support for JSON Schema Draft 7
ensures compatibility with industry-standard schema definitions and tooling, reducing the risk of vendor lock-in and
simplifying future migrations if required.

The open-source nature of AJV provides substantial advantages for long-term maintainability. The active community
ensures regular updates, security patches, and sustained support. The library's transparent codebase allows the team to
audit validation logic directly and contribute improvements if needed, fostering confidence in the validation layer's
integrity and compliance posture.

### Assumptions

- All JSON Schema definitions will adhere to the JSON Schema Draft 7 specification.
- Data validation will be performed at request/response boundaries and critical transformation points.
- The validation schemas will reference the direct PIES schema definitions alongside application code.
- The team maintains familiarity with JSON Schema Draft 7 syntax and best practices.

## Options Considered

- **Joi:** Built-in schema validation framework for object validation, but optimized for object shape validation rather
  than generic JSON Schema compatibility, and less performant for high-throughput scenarios.
- **Custom Validation Logic:** Would require significant development effort, increase maintenance burden, and introduce
  higher risk of implementation errors and inconsistent validation behavior.
- **AJV (chosen):** Exceptional performance and throughput, native JSON Schema Draft 7 support, active open-source
  community, minimal runtime overhead in Node.js environments.

## Consequences

### Positive

- High-performance validation minimizes impact on request/response latency and system throughput.
- JSON Schema Draft 7 compatibility enables use of standard tooling, documentation, and community resources.
- Active open-source community ensures ongoing maintenance, security updates, and feature development.
- Transparent codebase allows for code audits and custom contributions if specialized validation logic is required.
- Reduces development time by avoiding custom validation logic implementation.

### Negative

- Requires team training on JSON Schema Draft 7 syntax and AJV-specific configuration options.
- PEACH schema definitions must be carefully maintained to avoid inadvertent validation gaps or overly restrictive
  rules.
- External dependency on the AJV library requires monitoring for security advisories and compatibility updates.
- Complex nested schemas may become difficult to maintain without clear documentation practices.
