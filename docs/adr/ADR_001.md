- **Category:** Hosting, Infrastructure

## Context

We evaluated switching over from App Service to Container Apps (ACA) for PEACH API to explore potential cost savings,
scaling flexibility, and integration with Front Door.

Evaluation scope included:

- Creating a Terraform infra deployment of ACA with Azure Front Door - Premium and Private Link
- Private only Postgres Flexible Server access
- k6 load testing using 1 or 10 VUs for a GET and PUT Endpoints
- Compared ACA load test data against previous and new App Service load test data
- Looked into database and ACA connection behaviour, scaling, and queuing

## Decision

We will continue using Azure App Service for PEACH for the foreseeable future.

Note: Azure Container Apps could be a future option, but not right now due to below findings/consequences.

## Rationale

### Front Door Premium is required for ACA + Private Access

To expose a private Container App securely, Azure Front Door Premium is required due to Private Link Origin support

This introduces a [significant fixed monthly cost - $330](https://learn.microsoft.com/en-us/azure/frontdoor/compare-cdn-front-door-price).
For current traffic levels, this cost is not justified.

### ACA doesn't outperform App Service for our current usage

Load testing showed:

- GET performance improvement with ACA vs App Service was negligible and actually slower at lower user levels.
  Showing that it can scale up to potentially beat out App service but not enough to offset cost.
- PUT performance was worse on ACA, even with: higher CPU/memory, concurrency, and/or additional replicas.
  Possibly due to App Service having built in "buffer" handling scaling.

### Operational complexity outweighs benefits (for now)

ACA introduced a couple non-trivial operational issues:

- Manual Private Endpoint approvals (could possibly automate in CI/CD with scripts but not thought out yet)
- More moving parts to reason about during incidents

App Service:

- Already operational and performance is sufficient
- Front door will work without a Private Endpointb
- Can match ACA horizontal scaling with multiple instances

### Cost efficiency favours App Service at current scale

When factoring in:

- Front Door Premium
- Always-on minimum replicas
- Comparable or worse performance for writes

**App Service provides better cost-to-performance value** for current and near-term usage.

ACA’s cost model becomes attractive only when:

- Traffic is high enough to amortize Front Door costs
- Horizontal scale materially reduces latency
- Multiple services share the same ACA environment and Front Door

None of these are true today.

Additionally we can force traffic through a Front Door with App Service with only the Standard SKU level.

### Assumptions

- All providers can generate UUIDv7 identifiers using standard libraries.
- Database and logging systems can store and index UUIDv7 values efficiently.
- Distributed clocks across all provider systems are reasonably synchronized
  (clock skew tolerance is built into UUIDv7 design).
- The canonical UUIDv7 string representation (eight hex digits, hyphen, four hex digits, hyphen, four hex digits,
  hyphen, four hex digits, hyphen, twelve hex digits) is acceptable as the message format.

## Consequences

### Positive

- Lower monthly infrastructure cost
- Better write performance under burst load
- Can still utilize Front Door for public traffic control

### Negative

- Less scaling control than ACA
- Less alignment with container-native patterns
- Future migration will still require to be on app startup

### Future re-evaluation Criteria

- Sustained traffic growth requiring >2-3 App Service instances
- Clear DB-external bottlenecks (CPU-bound API work)
- Multiple internal services needing shared ingress
- Front Door Premium cost becomes amortized across workloads
